# Wordle 1v1

A React + TypeScript 1v1 Wordle-style game. The UI includes a playable local practice mode and a Supabase-ready boundary for authentication, realtime matches, and server-authoritative scoring.

## Run locally

```bash
npm install
npm run dev
```

The app runs in demo mode without environment variables. To connect Supabase, create `.env.local`:

```bash
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

Only the public anon key belongs in frontend environment variables. Never put a service-role key in this app.

## Supabase setup

1. Install the Supabase CLI and run `supabase link --project-ref <project-ref>`.
2. Apply `supabase/migrations/001_initial_schema.sql` with `supabase db push`.
3. Deploy the function with `supabase functions deploy submit-guess`.
4. Keep the answer, validation, match finalization, and ELO updates inside trusted database functions or Edge Functions. The browser should only receive tile statuses and opponent progress summaries.

The migration enables RLS. Players can read their own profile and matches they participate in, but opponent guesses are never exposed by a table policy. The opponent-board payload should be generated by a server function as statuses-only rows.

## GitHub Pages

The repository includes [.github/workflows/deploy-pages.yml](.github/workflows/deploy-pages.yml). It installs dependencies with `npm ci`, builds Vite, adds a SPA `404.html` fallback, and deploys `dist` with the official Pages actions.

In GitHub, open **Settings -> Pages**, set **Build and deployment -> Source** to **GitHub Actions**, then push to `main` or run the workflow manually from the Actions tab.

Add these repository or `github-pages` environment **Secrets** under **Settings -> Secrets and variables -> Actions**:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`

These values are injected only during the build. Do not commit `.env.local`, service-role keys, or any other Supabase secret. The publishable/anon key is expected to be embedded in the static frontend; database security comes from RLS and server-side functions.

For a project repository, the workflow automatically sets the base path to the repository name. For local builds, set `VITE_BASE_PATH` explicitly when needed:

```bash
VITE_BASE_PATH=/wordle-1v1/
npm run build
```

Supabase remains the backend; GitHub Pages only hosts the static frontend.

## Security model

- Supabase Auth identifies every player.
- RLS controls profile, match, and guess access.
- The answer is stored only in the match row and is never selected by the client.
- `submit-guess` validates ownership, word shape, guess count, and the server-side answer before returning statuses.
- Match resolution and ELO changes belong to a trusted transaction, with a unique finalization guard so a result cannot be applied twice.
